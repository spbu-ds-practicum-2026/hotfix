1. Состояния соревнования (Contest)  
     
   Соревнование определяется временными границами startsAt и endsAt.  
     
   До startsAt: Контест закрыт. Любая попытка отправить решение (POST /api/v1/submissions) отклоняется API с HTTP-статусом 409 CONTEST\_NOT\_OPEN.  
     
   Между startsAt и endsAt: Контест активен. Решения принимаются в очередь на проверку.  
     
   После endsAt: Контест завершен. Отправка новых решений отклоняется API с HTTP-статусом 409 CONTEST\_NOT\_OPEN. Однако фоновая проверка уже отправленных решений продолжается до их полного завершения (статус COMPLETED или SYSTEM\_ERROR).  
     
2. Логика заморозки турнирной таблицы (Freeze)  
     
   Состояние freeze (заморозка) активируется по флагу isFrozen в таблице соревнования.  
     
   Во время режима freeze публичный standings (турнирная таблица, отдаваемая через GET-запрос) перестает показывать новые результаты и изменения рейтинга.  
     
   Несмотря на то, что публичная таблица заморожена, внутренняя обработка submissions продолжается в обычном режиме. Воркеры проверяют решения и записывают результаты в базу данных (включая расчёт penalty и статуса решённых задач).  
     
   Участник продолжает видеть собственные вердикты за отправленные решения в личном кабинете, но не видит влияние этих решений на общую таблицу.  
     
   Снятие заморозки (Unfreeze): После снятия флага isFrozen (обычно после окончания контеста) публичная таблица мгновенно обновляется и показывает актуальный рейтинг с учетом всех проверок, прошедших за время заморозки.
